# DayNote — календарь записей в Telegram

**[Открыть бота](https://t.me/daynote_calendar_1102_bot)** · **[Канал автора — askjjkk projects](https://t.me/askjjkkproject)**

<img src="assets/avatar.jpg" width="180" alt="Аватарка DayNote: календарь с галочкой">

Личный блокнот с датами, вложениями и напоминаниями. Всё работает через сообщения и кнопки Telegram — без отдельного приложения.

## Возможности

- Главное меню, создание записи: текст → дата → время → подтверждение.
- Два способа выбора даты: календарь с перелистыванием месяцев или ввод `31.12.2026 14:30`.
- Список будущих записей по дате и времени; редактирование текста и перенос даты.
- Удаление с подтверждением.
- До 20 вложений на заметку: фото, файлы, видео, аудио, голосовые, стикеры и видеосообщения.
- Личные группы: создание, переименование, перенос заметок между группами. Удаление группы сохраняет записи.
- Напоминания за 15 минут, час, день, в момент записи или в своё точное время.
- Общая пауза для уведомлений и отдельные настройки каждой записи.
- Публичный доступ или закрытый режим по списку Telegram ID; данные каждого владельца разделены.
- Статистика для владельца: общее число пользователей и активность за 24 часа, 7 и 30 дней, без просмотра чужих заметок.
- Навигация обновляет сообщение вместо отправки нового на каждое нажатие.

Все даты и время — по Москве (UTC+3). Напоминание нужно включить отдельно: само сохранение записи его не создаёт. Перенос записи выключает старое напоминание. При включении общей паузы сохраняются индивидуальные настройки; при возобновлении прошедшие уведомления пропускаются.

## Статус

**Бот работает на Cloudflare Workers + D1.** Записи перенесены из локальной версии, ответ в Telegram и доступ к статистике проверены. Реальное напоминание после переключения пока отдельно не проверялось. Python-версия остаётся вариантом локального запуска.

В репозитории нет токена, реальных ID владельцев, записей клиентов, SQLite-базы или приватного SQL-импорта.

## Быстрый запуск: Python

Нужен Python 3.12+; внешних зависимостей нет.

```powershell
git clone https://github.com/askjjkk/daynote-calendar-bot.git
cd daynote-calendar-bot
py -3 -m venv .venv
Copy-Item .env.example .env
```

Создайте отдельного бота в официальном [@BotFather](https://t.me/BotFather). В локальном `.env` задайте:

```dotenv
BOT_TOKEN=your_bot_token
ALLOWED_USER_IDS=your_numeric_id,another_numeric_id
PUBLIC_ACCESS=1
ADMIN_USER_IDS=your_numeric_id
```

Используйте **числовые Telegram ID**, не username. `PUBLIC_ACCESS=1` открывает бота всем в личных чатах, `0` включает список `ALLOWED_USER_IDS`. `ADMIN_USER_IDS` даёт только агрегированную статистику через `/admin`: заметки других людей остаются недоступны. Статистика начинает собираться с первого обращения после обновления. Никому не отправляйте токен и не добавляйте `.env` в Git.

```powershell
.\.venv\Scripts\python.exe main.py --check
.\.venv\Scripts\python.exe main.py
```

На Linux: `python3 -m venv .venv`, затем `.venv/bin/python main.py`.

Откройте бота с разрешённого аккаунта и отправьте `/start`. `/help` покажет подробную инструкцию; `/cancel` отменяет текущий ввод. Кнопка «Изменить группу» доступна в карточке сохранённой записи.

Локальная версия работает, пока запущен процесс и включён компьютер. Второй процесс в той же папке блокируется. Не запускайте одного бота на нескольких компьютерах одновременно.

## Данные и резервная копия

Данные и очередь сообщений находятся в `data/calendar.sqlite3`. Вложения хранятся как Telegram `file_id`, сами медиа бот не скачивает. Не удаляйте `data`.

```powershell
.\.venv\Scripts\python.exe main.py --backup
```

Копия появится в `data/backup-*.sqlite3`. Она содержит личные заметки: не публикуйте её. При восстановлении остановите процесс, сохраните текущую базу отдельно и восстановите выбранную копию. SQLite WAL-файлы должны принадлежать той же версии базы; не смешивайте файлы разных копий.

При сетевых сбоях отправка повторяется. В редком случае потери ответа Telegram возможна повторная доставка. После простоя локальная версия отправляет пропущенные уведомления с отметкой о задержке. Если Telegram блокирует отправку, ошибка сохраняется; после разблокировки настройте напоминание заново.

## Cloudflare Workers + D1

Исходники лежат в `cloud/`: чистая логика диалога, D1-хранилище, webhook, минутный cron и очередь доставки. Нужен Node.js 24+ и аккаунт Cloudflare.

```sh
cd cloud
npm install
npm test
npx wrangler login
npx wrangler d1 create daynote-calendar-db
```

В `wrangler.jsonc` замените `REPLACE_WITH_YOUR_D1_ID` на ID созданной базы. Затем:

```sh
npx wrangler d1 execute daynote-calendar-db --remote --file schema.sql
npx wrangler secret put BOT_TOKEN
npx wrangler secret put ALLOWED_USER_IDS
npx wrangler secret put WEBHOOK_SECRET
npx wrangler deploy
```

В `WEBHOOK_SECRET` задайте случайную строку из букв, цифр, `_` и `-` длиной не менее 32 символов. Перед переключением сделайте резервную копию и остановите локальный polling. Зарегистрируйте Telegram webhook на `https://<your-worker>.workers.dev/telegram` с таким же `secret_token` и `allowed_updates` из `message` и `callback_query`. Не помещайте токен в публичный URL и не публикуйте команды с его значением.

`GET /health` возвращает только статус сервиса. Webhook проверяет секретный заголовок и список владельцев. Изменения состояния защищены проверкой версии; очередь переживает повторную доставку updates. Напоминания проверяются раз в минуту, поэтому возможна задержка около минуты плюс задержки сети.

Для переноса существующих данных предусмотрен `cloud/export_sqlite.py`: запускайте из корня проекта после остановки локального процесса. Он создаёт приватный `cloud/private/import.sql`, который нужно импортировать **в новую пустую D1 после schema.sql**. Сначала проверьте количество объектов и сохраните резервную копию. Если в локальной очереди есть неотправленные ответы, экспорт останавливается.

Free-тарифы имеют ограничения и не гарантируют отсутствие сбоев. Планировщик обрабатывает до двух пользователей за запуск; при одновременной нагрузке уведомления могут задерживаться. Перед использованием проверьте текущие [лимиты Workers](https://developers.cloudflare.com/workers/platform/limits/) и [D1](https://developers.cloudflare.com/d1/platform/limits/). Не включайте платный тариф без своего решения.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --test cloud/test/*.test.mjs
```

Тесты проверяют создание, ручные даты, навигацию, редактирование и удаление, группы, вложения, изоляцию владельцев, перезапуск, повторы updates, конкурентные изменения и повтор доставки. Облачные тесты используют SQLite в памяти; сами по себе они не подтверждают производственный деплой или реальные лимиты CPU Workers Free.
